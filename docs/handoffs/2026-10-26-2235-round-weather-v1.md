## What was done

**Research.** The full findings, with sources, are in `docs/plans/round-weather.md`, "What the game code shows". The decompiled MP assemblies are in the scratchpad (`...\scratchpad\mpdecomp\`), not in the repo. In short:
- **Multiplayer opens missions with an empty atmosphere,** so the scene keeps its own. The load-time atmosphere goes to native code through `MissionInitializerRecord.AtmosphereOnCampaign` and can't be repeated.
- **Mid-mission, the game changes atmosphere with `Scene.SetAtmosphereWithName`.** The NavalDLC story mission switches it four times in one battle. Nothing shipped calls `SetRainDensity` or `SetFog`; rain and fog come with the preset.
- **`TOD_NN` presets are morning hours, symmetric around noon.** `TOD_05` is 19:00, `TOD_04` 20:00 (dim), `TOD_03` nearly black. The singleplayer table maps 15 → `TOD_04` and 18 → `TOD_03`, both wrong.
- **Multiplayer has no weather rules,** no `ApplyWeatherEffectsModel` and no stat model reads, so weather can be visual only with nothing to switch off.
- **The dedicated server has no SandBox module,** so it can't read `sp_battle_scenes.xml` for terrain.
- **No scene is marked snowy.** The campaign's snow comes from winter, which is set at load only.

**The user's decisions:**
- rare weather: clear 70%, overcast 15%, light fog 6%, thick fog 4%, rain 5%;
- visual only;
- snow "try it, drop if broken": dropped for the data reason above;
- the admin fixed-weather option later.

## Traps

- **Atmosphere preset names lie about the hour.** Trust `sun_altitude` / `sun_intesity` in the XML, not the name or its `time_of_day` value.
- **A few presets' internal name differs from the file name** (`TOD_06_30_Cloudy_sunset2.xml` is named `TOD_06_30_cloudy_sunset2`). It is unknown which one `SetAtmosphereWithName` matches, so v1 avoids them.
- **`dotnet msbuild -t:Compile -p:TargetFramework=X` checks a build without deploying** (`DeployModule` hangs off `Build`). Restore with `-p:TargetFramework` narrows the assets file to that framework, so run a plain `dotnet restore` afterwards.
