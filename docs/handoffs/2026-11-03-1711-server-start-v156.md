# Handoff: starting the dedicated server on v1.5.6

Session of 2026-11-03, written 17:11, on branch `rbm-combat` (worktree `Modules\CommanderBattleProject-rbm-combat`), uncommitted.

## What was done

- **The server would not start.** Steam moved the dedicated server to the v1.5.6 beta on 2026-10-30 (buildid 26320246, `BetaKey "beta"`). Every start, vanilla included, ended silently right after the module DLLs loaded: no exception, no crash dump.
- **Cause:** `DedicatedCustomServer.Starter.exe` adds `/playerhosteddedicatedserver`, which loads Multiplayer's WebPanel and ListedServer.MapServer submodules (tag `PlayerHostedDedicatedServer`). They target .NET 8. The server runs on its bundled .NET 6 (`bin\Win64_Shipping_Server\Microsoft.NETCore.App`, 6.0.12; without it the native host crashes). v1.5.6's `Module.CollectModuleAssemblyTypes` returns `CriticalError` on a type-load failure, and on a dedicated server that means `AbortGame` with no message. Verifying the files in Steam changed nothing.
- **Fix:** `tools/Start-Server.ps1` starts the host `TaleWorlds.Starter.DotNetCore.exe` directly, with `/dedicatedcustomserver <port> USER 0` (what the Starter adds) and without the player-hosted flag. It takes the pid from `Start-Process -PassThru` and recognises both process names as a running server. The by-hand command is updated in `CLAUDE.md`, `README.md` and `manual/docs/getting-started.md`. There is no web panel and no map download server.
- **Checked:** `-Restart` started pid 31616 on `battle_terrain_001`, `124 classes applied, 0 failed, 11 skipped; RBM Combat on`. The server talks to TaleWorlds' beta services (`game-test6.bannerlord-services-3.net`), so the beta client may now be able to join. That hasn't been tried.
- `-Build` earlier in the session installed this worktree's DLLs (server and client) over whatever was there.
