## What was done

The user asked for a hint, when they are down, that F plays as the soldier they are spectating.

**How it works in stock**
- A dead player presses the action key (combat key 13, F by default). `MissionMainAgentController` then sends `RequestToSpawnAsBot`. It does this only while the peer has a `FollowedAgent`.
- The server sets `WantsToSpawnAsBot` only if the peer's respawn timer has expired. In this mode that timer is 3 s after death: the stock `SpawningBehaviorBase.GetMaximumReSpawnPeriodForPeer`, which `CommanderBattleSpawningBehavior` doesn't override.
- `CheckForCommandersTakingOverSoldiers` then takes the followed soldier if it is in the formation. `FollowedAgent` is synced from the client by `SetFollowedAgent`.

**Why the hint never showed**
- The stock multiplayer spectator card (`MultiplayerSpectatorHUD.xml`) already has the line `str_sergeant_battle_press_action_to_control_bot_2`, "Press {USE_KEY} to take control", filled with the player's own binding.
- `MissionMultiplayerSpectatorHUDVM.OnSpectatedAgentFocusIn` turns it on only when a `MissionMultiplayerGameModeFlagDominationClient` is present. Commander Battle has none.
- Found by decompiling `TaleWorlds.MountAndBlade.Multiplayer.ViewModelCollection` / `.GauntletUI` / `.View` with `ilspycmd`, into the session scratchpad. They are not in the RBM decompiled folder.

**The fix**
- `CommanderBattleTakeOverHintView` sets the public `CanTakeControlOfSpectatedAgent` on the stock card every tick. It reaches the card through `MissionGauntletMultiplayerHUDExtension.DataSource.SpectatorControls`, which is public, so there is no reflection or patch.
- It is set every tick because the stock card clears it whenever the camera moves to another soldier.
- It is true when all of these hold:
  - the player's agent died this round and 3 s have passed;
  - the round is in progress;
  - the followed agent is active and AI-controlled;
  - it is in the player's `ControlledFormation`.
