# One module: RBM.Multiplayer folded into CommanderBattle

Written 2026-11-16 21:06.

## What was done

Commander Battle is now one Bannerlord module, `CommanderBattle`. The four projects and their DLLs are unchanged; only where they install and who lists them changed.

- **Module definition.** `Module/SubModule.xml` lists all four DLLs (CommanderBattle, CommanderBattle.View, RBM.Multiplayer, RBM.Multiplayer.View, in that order) and RBM's XML nodes after Commander Battle's own. `RBM.Multiplayer/Module/SubModule.xml` is deleted.
- **Build.** `Directory.Build.props` loses `RbmMpModuleOutputDir` and `RbmMpDedicatedServerModuleDir`. `RBM.Multiplayer.csproj` and `RBM.Multiplayer.View.csproj` build and deploy into `ModuleOutputDir` / `DedicatedServerModuleDir`. `RBM.Multiplayer/Module/ModuleData/` (`project.mbproj`, `rbm_mp_core_parameters.xml`) stays where it is and is copied into the one module.
- **Team AI.** `CommanderBattle/MissionMultiplayerCommanderBattle.cs` asked `ModuleHelper.IsModuleActive("RBM.Multiplayer")` to leave out `CommanderBattleTactic`. It now checks whether the `RBM.Multiplayer` assembly is loaded.
- **Scripts.** `tools/Start-Server.ps1` starts `Native*Multiplayer*CommanderBattle` and has no `-NoRbm`. `tools/Package-Release.ps1` zips one folder and checks for all five client DLLs.
- **Docs.** `README.md`, `CLAUDE.md`, `manual/docs/getting-started.md`, `manual/docs/settings.md`, `manual/docs/features/rbm.md`. Players updating from v0.2.1 must delete `Modules\RBM.Multiplayer`.
- **Installed.** Built and installed on both sides; the old `Modules\RBM.Multiplayer` folders were removed from the game and the dedicated server.
