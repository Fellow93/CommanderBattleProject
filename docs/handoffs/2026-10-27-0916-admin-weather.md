## What was done

The user asked for an admin to change the time of day and the weather. A new map reverts to random, and random is the weighted draw.

- **Admin panel** (`CommanderBattle.View/CommanderBattleAdminPanel.cs`). Two choices in the Commander Battle group:
  - Time of Day: Random, Morning, Afternoon, Noon, Dusk;
  - Weather: Random (weighted), Clear, Overcast, Light fog, Thick fog, Rain.
  - They open on the setting the client last got from the server. `SendOptions` (Apply Changes) sends `RequestWeatherOverride` when either changed.
- **Messages** (`CommanderBattle/Network/WeatherOverride.cs`, `RequestWeatherOverride.cs`): time and weather, -1 for random.
- **The pick** (`CommanderBattle/CommanderBattleWeather.cs`):
  - `ForcedTime` and `ForcedWeather`, set with `SetForced`;
  - `GetPick` draws both from the seed, then puts the fixed parts in;
  - `DescribeForced` for the announcement;
  - `GetTimeName` is now public, and `GetWeatherDisplayName` is new.
- **Server** (`MissionMultiplayerCommanderBattle.Admin.cs`):
  - `CheckAdmin` is now shared with the other commands.
  - `SetWeatherOverrideFrom` sets the values, logs "Admin X: weather set to ...; round N weather: ...", broadcasts `WeatherOverride`, announces "<admin> set the weather: ..." and applies it for a playing host.
  - `MissionMultiplayerCommanderBattle.cs` registers the handler, and sends `WeatherOverride` before `SpawnLayoutSeed` to a player who joins.
- **Client** (`MissionMultiplayerCommanderBattleClient.cs`):
  - `UpdateWeather` replaces the seed-only check: it applies whenever the round's pick changes, from a seed or a `WeatherOverride`, and shows the chat line.
  - `OnBehaviorInitialize` resets the setting each mission. That behaviour runs on the server too, so a new map starts random everywhere.
  - `RequestWeatherOverride` sends the panel's choice.
