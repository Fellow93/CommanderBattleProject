# Unit editor

Written 2026-11-17 13:22.

## What was done

Built the unit editor of [docs/plans/unit-editor.md](../plans/unit-editor.md): a local page that edits a culture's units in RBM mode, with an item catalogue the game writes.

- **Item catalogue.** New `RBM.Multiplayer/RbmItemCatalogue.cs`, called from `RbmItemSetCheck.Log()` with the stats fingerprint. It writes `tools/UnitEditor/unit-editor-data.js` (every item but the `mp_` ones, in the shape of RBM's troop loadout editor) when the repo's `tools\UnitEditor` folder exists next to the game or the dedicated server. The tier comes from the item id (`_tN`); there is no value field, because multiplayer has no item value model. The file is gitignored (`.gitignore`).
- **Core.** `tools/UnitEditor/unit-editor-core.js` reads a culture's three files (`cb_mpclassdivisions_`, `cb_mpcharacters_`, `cb_rbm_loadouts_`) and edits them by text splices: slots, rosters, setups, unit properties, adding and deleting units (deleting keeps the comments above the unit). It uses RBM's `troop-loadout-core.js` from the sibling repo. `tools/UnitEditor/unit-editor-test.js` runs 31 tests under node.
- **Page.** `tools/UnitEditor/index.html`: open the ModuleData folder, pick a culture; unit list by formation class with weight labels and "+ unit" / "Delete unit"; unit properties (name, formation class, multiplier with its weight label, cost, icon, AI and speed values, hero and troop level and skills), validated before they are written; gear tabs with the item picker; setup tabs with name, description, icon, move, delete and "+ setup"; problems list; Save, which re-reads the files first, names the files written and not written when a write fails, and cannot run twice at once.
- **Server.** New `tools/UnitEditor/serve.js` (`node tools\UnitEditor\serve.js [folder] [port]`, port 8123) serves the page and reads and writes `Module\ModuleData`, so no folder is picked; over http the page uses it through the same load and save code (`serverDir`). It listens on 127.0.0.1, refuses other `Host` names, and touches only existing `cb_*.xml` files. The read-only `?dev=<culture>` mode is gone. `.claude/launch.json` starts the server. Checked on a copy of the unit files: load, a one-line save, the refusal when the file changed on disk.
- **Review fixes.** The hero's and the troop's names are edited separately (`setCharacterName`; `setName` is gone); `setRole` refuses the last unit of a formation class; at most 16 setups per unit; a first entry keeps a comment inside its element; `Setup index="0"` and a setup perk without a `Setup` are problems; focus stays put after a field edit; Save takes its file handles at click time and locks the culture list and Open while writing; `RbmItemCatalogue` survives a nameless item. The value tests run on a frozen copy of the empire files, `tools/UnitEditor/test-data/` (38 tests now).
- **Docs.** `tools/UnitEditor/README.md`, a section "Editing RBM units" in `README.md`, a line in `CLAUDE.md`, the plan's status and two corrections in `docs/plans/unit-editor.md` and `docs/plans/README.md`. The step-by-step plan is `docs/plans/unit-editor-implementation.md`.
- **Power.** Design in `docs/plans/unit-power.md`. `unit-editor-core.js` gained `power` (a port of RBM's singleplayer `StrategicTroopPower`: weapon class and skill, draw energy for Ranged and Horse archer units, parry, armour zones, shield, mount; the troop's rosters averaged), `menOf` (the game's men per formation from `multiplier`) and `levelClass` (sets a class's multipliers to `k / power`). The page shows power, men and the formation's strength within its class in the unit list, the parts of a unit's power in its detail, "Level this class", and a men field next to `multiplier` that sets the multiplier for a typed men count (`setMen`). The page explains its numbers: a legend above the unit list, a line under each property field on what it does in the game, a sentence under the power's parts. 45 tests. Checked on a copy of the empire files: levelling infantry took 79/101/120% to 99/100/101% and saved three `multiplier` lines only.

Not checked: the men against a server's class log, saving through the folder dialog when the page is opened from disk, the catalogue written by a client (only the dedicated server wrote it), and a new unit in game (class log, selection screen, RBM gear). Nothing is committed.
