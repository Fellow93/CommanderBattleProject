## What was done

The user asked for simple, readable logs with only the important things in them.

- `CommanderBattleLog` and `RbmMpLog` each have `Detail(message)`. It writes only while the logger's `Detailed` flag is on, and the flag defaults to `false`. Turning it on means changing the code and rebuilding.
- `CommanderBattleLog`'s first-chance hook only logs exceptions whose stack passes through our code (`at CommanderBattle.` or `at RBM...`, minus the logger's own frame). Lobby and HTTP exceptions are gone. The prefix is now "Exception" instead of "first-chance".
- Lines that are still always written:
  - mission opening, "Joining X instead of advertised Y";
  - `Round N: <state>`, and the new `Round N over: attackers win / defenders win (time ran out), A attackers and D defenders left`;
  - "X commands Side formation N", "X picked ... from next round";
  - the order-bar fix line from 23:53;
  - campaign maps, only when some were missing;
  - a troop class warning, only when a culture has more classes than the troop index can reach;
  - the RBM patch summary, and every failure or fallback line.
- Lines moved to `Detail`:
  - periodic status, fleeing, team AI, RBM tactics, formation status, Frontline and archer counters;
  - spawn path, deployment plan, spawn jitter, layout seed, per-formation spawn and placement;
  - troop count tables, "now fields", class lists, splits;
  - lifecycle traces (`Client.*`, `GameMode.*`, `Spawning.Initialize`), preparation marker lines, agent stats and RBM settings;
  - RBM resets, terrain, "tactics registered", "behaviours added", skipped patch classes.
- `README.md` has a new "Logs" section, and the RBM log note was changed. `CLAUDE.md` has a new log description and the rule: `Write` only for what a reader needs, diagnostics through `Detail`.
